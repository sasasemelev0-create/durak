# 🃏 Дурак — Telegram Mini App

Рабочий прототип: движок правил + сервер реального времени + интерфейс Mini App.
Играется от 2 до 6 игроков, лобби с настройками, профиль, режимы «с шулерами» и «классика/ничья»,
5 возвратов карты за партию.

## Запуск локально

```bash
cd durak
npm install
npm run dev            # без BOT_TOKEN — режим разработки
# открыть http://localhost:3000
```

В dev-режиме подпись Telegram не проверяется, каждый браузер получает свой профиль —
удобно тестировать вдвоём в двух окнах.

## Тесты

# Что осталось сделать тебе

## 1. Создать бота (5 минут)

1. Открой [@BotFather](https://t.me/BotFather) → `/newbot` → задай имя и username.
2. Получи токен вида `123456:ABC-DEF...`.
3. Пропиши его в переменную окружения:

```bash
export BOT_TOKEN="твой:токен"
npm start
```

С этого момента сервер проверяет подпись `initData` — подделать игрока нельзя.

## 2. Привязать Mini App

1. В BotFather: `/newapp` → выбери бота → название → загрузи иконку 640×360.
2. BotFather попросит URL — там должен быть **HTTPS**.
3. Ещё пригодится `/setmenubutton` — кнопка меню слева от поля ввода.
4. Для теста можно `/setdomain`, но проще сразу взять нормальный хостинг.

## 3. Захостить

Нужен HTTPS-домен. Варианты по возрастанию сложности:

**Быстро (бесплатно):**
- [Railway](https://railway.app) / [Render](https://render.com) / [Fly.io](https://fly.io) — пуш репозитория, задаёшь `BOT_TOKEN`, получаешь домен.
- Один процесс Node.js, WebSocket работает из коробки, ничего настраивать не надо.

**Свой сервер:**
```bash
# на VPS
git clone <репо> && cd durak && npm install
BOT_TOKEN=... PORT=3000 npm start

# nginx + сертификат
server {
  server_name durak.example.com;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
  }
}
```
Заголовки `Upgrade`/`Connection` обязательны — без них WebSocket не поднимется.
Сертификат: `certbot --nginx -d durak.example.com`.

Docker-вариант — в `Dockerfile`.

## 4. Подключить базу данных

Сейчас профили и лобби живут в памяти: после перезапуска всё сбрасывается.
Минимум — одна таблица:

```sql
CREATE TABLE players (
  id          TEXT PRIMARY KEY,      -- telegram user id
  name        TEXT NOT NULL,
  username    TEXT,
  photo       TEXT,
  wins        INT DEFAULT 0,
  losses      INT DEFAULT 0,
  games       INT DEFAULT 0,
  created_at  TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE games (
  id         SERIAL PRIMARY KEY,
  room_id    TEXT,
  seed       BIGINT,                 -- для проверки честности
  opts       JSONB,
  players    JSONB,
  losers     JSONB,
  finished_at TIMESTAMPTZ DEFAULT now()
);
```

Заменить `Profiles` в `server/auth.js` на запросы к `pg` — интерфейс класса уже готов (`upsert`, `get`, `recordResult`, `public`).

## 5. Монеты и баланс (когда решишь)

Код писался с расчётом на это, но сами монеты не добавлял — как просил. Когда понадобится:

1. Таблица `wallets (player_id, coins, crystals)` + `transactions (id, player_id, delta, reason, created_at)`.
2. **Никогда** не пиши баланс из клиента — только транзакции на сервере.
3. Ставка при входе в лобби блокируется (`delta: -bet, reason: 'bet_lock'`), возвращается при отмене.
4. Покупка монет — Telegram Stars (`sendInvoice` с `currency: 'XTR'`).
5. ⚠️ Если монеты можно будет выводить в реальные деньги — это азартная игра: нужна лицензия, 18+, KYC. Telegram Stars для такого использовать нельзя. С виртуальной валютой без вывода — ограничений нет.

## 6. Чего в интерфейсе ещё нет

Функционально играется всё, но для «полного клона» стоит добавить:

- **Таймеры хода.** Сейчас ход не ограничен по времени. Нужен `setTimeout` на сервере: 30 с на ход, при просрочке — автобой/автовзятие.
- **Анимации карт.** Сейчас карты появляются мгновенно, без перелёта из руки на стол.
- **Звуки** — шлепок карты, «бито».
- **Чат и эмоции** за столом.
- **Кнопка «Выйти из игры»** посреди партии — движок умеет (`out: true`), кнопки нет.
- **Экран правил** — сейчас пункт «Правила» в профиле не кликабельный.
- **Друзья, доска почёта, турниры** — не начинали.

## 7. Тонкости, на которые я наткнулся

- **Зависание партии.** Два бота могут бесконечно перекидывать карты, не закрывая кон. Добавил предохранитель: если `n×4` конов подряд ничего не ушло в отбой — партия завершается по числу карт на руках. Живому игроку это не грозит, но защита нужна.
- **Защищающийся не может подкидывать** в текущей реализации — только отбиваться, переводить, брать или закрывать кон. Если захочешь «подкидывать после отбоя» — это правка в `canAttackWith`.
- **Добор карт** идёт атакующему первому, потом по кругу — как в живой игре. При 6 игроках и колоде 24 карт на всех не хватит, последние играют тем, что есть.
- **Порядок атакующих** при 6 игроках: если атакующий вышел, ход переходит к следующему активному.

## 8. Проверить честность раздачи

Каждая партия получает `seed`. Если игрок жалуется на «подкрученную» колоду — по seed можно восстановить точную раздачу:

```js
import { Durak } from './server/engine.js';
const g = new Durak({ players, deckSize: 36, seed: 123456 });
// g.players[i].hand — та же раздача, что была в партии
```

Стоит показывать seed в конце партии — это снимает половину подозрений.
